作るものと判断の基準

制作物

平面マップを歩くキャラクターの歩行グラフィックです。部位ごとに素材を用意し、支点・関節・重なりを連動させて動かすことが目的です。静止絵を単に上下させるものではありません。

最初は白い髪、輪、翼、白い衣装を持つルミナでした。その後、歩行を他のキャラクターにも使えるようにプレーンな素体へ一般化する指示がありました。現行はこの素体の制作段階です。ルミナの初期素材は失わないよう履歴に収録しています。

最初の発言は「四種類」と書かれていますが、列挙は5方向です。後続で斜め下・斜め上・後ろの追加が明示されたため、現行は5方向です。「上」は見上げる顔ではなく、マップ上方へ進む後ろ向きです。

各方向192×256 px、透過RGBA。1歩4コマ、左右合わせて8コマ、120 ms/コマ、1周期960 msです。ヌルヌルしすぎない動きが希望なので、フレーム補間を追加しません。頭・上半身は歩行に連動して上下します。

維持する見え方

  • 肩は張らせず、首元から肩先へ自然に下がる形。正面の腕の横移動で肩幅が増えたように見せない。
  • 胴体を長くしすぎず、骨盤の正面を尻の二つの膨らみのように描かない。少し低めの等身。
  • 腕は直線の棒にしない。上腕・肘・前腕・手首・手を連動し、肘を固定したロボットのような振りを避ける。
  • 正面の腕を体へ押し付けない。肩の幅を広げて解決するのでなく、肘・手首と胴体の間に余裕を作る。
  • 手首と指は伸びきらせず、進行方向・前腕の角度に沿う。親指・肘の向きを誤反転しない。
  • 脚は股関節から動かす。膝を前へ運び、前に出した下腿を伸ばしてから踵が着く。足を地面と平行のまま固定しない。
  • 膝関節と太腿・下腿は前後関係で隠れ方を変える。関節の丸を常に最前面へ貼ると、膝が逆向きに見える。
  • 正面でも足裏の見え方を変える。踵着地、足裏支持、踵上げ、つま先の蹴り出しを区別する。
  • 分割した部位の切り口がトゲ・二重線・喉元の突起にならないようにする。

頭・首で最優先にすること

ユーザーは繰り返し、斜めでは無理に正面・横・後ろと高さを合わせなくてよいと伝えています。比較の水平線や同じ数値を優先しないでください。

首の見え方は、首素材だけでなく、胴体に描かれた首、頭の輪郭、重なり、方向による短縮の合成結果です。独立した首素材を何画素見せるかだけで頭の高さを決めると、棒の上に頭が載る形へ戻ります。

位置を直す前に、顔の輪郭・目・耳・顎・後頭部が胴体の向きと合っているかを確認します。v7でこの絵も変更しました。v8では首の切り口の横線を修正しました。v9以降は配置調整です。

v9で頭が前へ出すぎたため、v10〜v13で背中側へ戻しています。直近の「もう少し」はこの同じ操作の継続でした。原寸pxで指定されており、2倍表示の画面のpxではありません。

座標と描画

画面左上が原点、Xは右が正、Yは下が正。角度は度、画面上で正が時計回りです。ローカル画素 p、画像内支点 pivot に対し、画面位置は次です。

world = position + Rotate(angle) × Scale(scale_x, scale_y) × (p - pivot)

rig.json の各 ops を配列順に奥から手前へ描きます。position は計算済み画面座標です。parent は接続関係を示す情報であり、描画時に親の移動をもう一度加算しません。負のscale_xは左右反転です。

画像はNearest Neighborで扱います。拡大表示の倍率を座標に混ぜないでください。PNGは192×256、通常の確認表示は2倍です。

部位と連動

1方向17基本部位、正面と追加3方向に足差分3枚ずつ、合計97素材です。左右の腕・脚へ素材を使い回すため、1コマは29描画操作です。

上腕・前腕・上腿・下腿は pivot から end までを隣接する関節間へ伸縮・回転させます。基本長は上腕22、前腕17、上腿26、下腿28 pxです。斜め・正面では画面への投影による短縮もscale_yへ入ります。

far / near は部品の識別名です。正面では画面左／右、横では奥／手前、斜めではニュートラル姿勢の奥／手前の列に由来します。歩行中の実際の重なりはdepthで変わります。名前だけで全コマの前後を固定しないでください。

背中側へさらに動かすとき

今の斜め2方向は右を向いているので、今回の調整での背中側は画面左です。原寸で2 pxなら、対象方向の neck_tip_offset[0] から2を引きます。首の上端と頭が同時に移動します。高さを保つ場合、Y、頭pivot、head_offset は変えません。

画像のpivotを変える修正と、首上端の座標を変える修正を重ねると二重に移動します。どちらを変えたかを明記し、全8コマの差分で確認します。

肩・脚・足・描画順

斜めの肩は胸郭画像の shoulder_sockets へ登録しています。絵と骨格がずれないよう、肩の補正量を肘・手首にも同じだけ加えます。

脚は股関節が起点です。横向きの脚軌道を元に方向へ投影し、奥行きで骨盤・太腿・膝・下腿の順序を変えます。足画像の opaque_corners は接地計算用です。足を差し替える場合、見かけの矩形の底ではなく、不透明画素の輪郭と足首pivotを更新します。

正面・横向きの基準地面はy=242。追加3方向は ground_center=237.5 とdepthに基づく高さを使用し、斜め下は地面の傾きも考慮します。

頭は現行では最後、首は胸郭の前に描かれて胸郭が下端を覆います。腕・脚の順序は位相で変わるため、全コマ共通の固定一覧を手で再現せず、各コマのops順を使ってください。

歩行と見た目の確認

動きの設計

1周期8コマで左右の脚は4コマずれます。正面のfar/nearと横・斜めのfar/nearは対応の定義が違うため、脚の位相は rig.json の各hipの phase で確認してください。

横向きの股関節から足首へ2節の脚を解き、斜めの3方向はその膝の曲げ・足の浮き・腕のタイミングを引き継いで投影します。着地時に膝が大きく曲がったままにならず、前へ伸びた下腿の先の踵が着きます。

確認の順番

  1. 通常サイズのGIFで、全体の体重移動・前傾・腕の振りを見る。
  2. 斜め2方向だけを並べ、頭が胸郭に対して前へ出すぎていないかを見る。他方向の頭頂線に合わせない。
  3. 一時停止して全8コマを見る。踵着地、通過、蹴り出し、遊脚で脚や足の輪郭が破綻しないか確認する。
  4. 首・肩・肘・膝・手首・足首を拡大する。隙間、切り口の線、トゲ、裏向きの関節を確認する。
  5. 関節表示をオンにし、骨盤から胸郭・頸部までのつながりと股関節の起点を見る。骨格線を消した最終表示にも戻る。
  6. 変更対象以外の方向と、変更していない部位の動きが維持されているか比べる。

特に、腕と胴体の間の余裕、肩幅、正面骨盤の形、足裏の切り替え、斜めのつま先と進行方向の一致を見てください。数値検証が通っても、目や耳の向き・シルエットは別途確認が必要です。

検証スクリプト

validate.cjs は関節の接続、脚長、着地、膝と肘のタイミング、足の投影、肩の登録位置を確認します。validate-heads.cjs は胸郭側の首も含む最終的な首元と頭の重なりを確認します。validate-player.cjs はNodeのCanvas実装で操作を確認します。

以前の首検証は独立した首素材の見える画素数を要求しており、頭を高くしてしまう原因になりました。現在の検証はその条件を変更しています。検証を満たすために見た目を元の不自然な配置へ戻さないでください。

ブラウザー実機でのページレイアウト検証は実施済みとはしていません。旧版のREADMEの評価も当時のものです。パッケージの検証結果は data/validation-report.txt に残します。

失敗の原因を引き継ぐ

首・頭

首の支点だけを動かしていた段階では、顔がほぼ正面なのに目だけ右へ寄った絵や、斜め後ろの耳・後頭部の向きの問題が残りました。絵と配置を区別して確認します。

頭を下げるだけでは首が完全に隠れることがあり、反対に首を見せるために持ち上げると細い棒の上へ頭が載りました。胸郭にも首が描かれているため、独立した首素材を継ぎ足す前提を外し、肩の間から頭蓋底への接続へ変更しました。

v9の前方移動はユーザーから「前につんのめりすぎ」と指摘されました。現在はその後の背中側への調整をすべて反映しています。v9の配置を正解として復元しないでください。

線・突起

首の切り口の濃い輪郭、髪の束、足の分割の重複など、いくつかの別の原因がありました。一律に頭や足をずらすのでなく、どの画像・描画順の画素かを特定して直します。v8の首の線の修正は現行素材へ残っています。

腕・脚

腕を内側へ寄せすぎると胴へ押し付けたように見えます。肘の固定、手首や指の伸びきり、足首の水平固定もぎこちなさの原因でした。直線的なパーツを曲げるだけでなく、シルエットと位相差を確認します。

前脚は膝を前へ運んだ後、下腿を前へ伸ばして踵を着けます。膝が曲がったまま、下腿が後ろへ残る形へ戻さないでください。正面の骨盤・膝の見え方には重なり順も影響します。

確認の不足

過去には骨格の整合や首の画素の存在を確認していても、ユーザーが見て違和感のある結果が残りました。検証スクリプトの成功を、自然な見え方の証明やユーザーの承認として扱わないでください。

開く・修正する・再出力する

閲覧

ZIPを展開し、START_HERE.html または workspace/plain-walk-v13/plain-walk-player.html を開きます。現行プレイヤーの画像・コード・設定は埋め込み済みで、サーバーや通信は必要ありません。GIFでも確認できます。

プレイヤーでは5方向、斜め2方向を含む方向別表示、停止・コマ送り、関節表示、部品一覧、腕振り・肘・速度の調整、配置JSON保存を扱えます。OSの動きを抑える設定により停止状態で開く場合があります。

再出力の環境

Python 3、Pillow、NumPy、Node.js、@napi-rs/canvas が必要です。現行 package.json はcanvas 0.1.100を指定しています。依存ライブラリーや実行環境自体はZIPへ複製していません。

cd workspace/plain-walk-v13
python -m pip install -r requirements.txt
npm install

必要なら作業用にフォルダーを複製してから変更します。この統括ZIPの元データを上書きせず比較元として残せます。

位置・動きだけを変えた場合

config.json または rig.js を変更し、次を実行します。

node validate.cjs
node validate-heads.cjs
node render.cjs
python assemble.py
node validate-player.cjs

renderは40コマ、計算済みrig、埋め込みHTMLを書き直します。assembleはGIF、APNG、シート、パーツ一覧を書き直します。config.json だけを変えても、既に書き出されたHTMLやGIFへ自動では反映されません。

素材を元画像から再生成する場合

python rebuild.py

これは extract_parts.py で元アトラスから部位PNGとassets.jsonを作り直し、検証・描画・組み立てを行います。画像生成サービスへの呼び出しは不要です。必要な元絵は同梱済みです。

部位PNGやassets.jsonだけを直接編集すると、次のrebuildで上書きされます。恒久的な変更は、元絵とextract_parts.pyにも反映してください。斜めの頭pivotとcervical_socket、v8の首の開口の修正もextract_parts.pyに記録されています。

比較画像の更新

元のrebuildは head-neck-comparison.png、head-turnaround.png、diagonal-8frames-check.png の3枚を自動更新しません。これらは各版の確認時に作った画像です。このZIPには更新用の補助スクリプトを追加しました。

パッケージ直下で実行する例：

python scripts/refresh_reviews.py --current workspace/plain-walk-v13 --previous workspace/plain-walk-v12

新しい版を作ったら、引数を新しい版と比較元の版へ置き換えます。通常のPNG/GIFの書き出し後に実行してください。

引き継ぎでの確認

scripts/verify_package.py は、梱包時のSHA-256とサイズでファイルを照合します。ZIPの展開直後に実行できます。ファイルを編集した後に不一致となるのは通常の結果です。

python scripts/verify_package.py

旧版やルートの検証スクリプトは当時の作業状態も含めて保存しています。古い絶対パスや環境依存の参照が残るものがあります。通常の継続作業には現行plain-walk-v13のコードを使い、旧版は比較・原因確認のために参照してください。

ルミナへ戻す場合の注意

最新素体へ衣装・髪・翼を載せる作業は、現行版で完了していません。旧ルミナの見た目は workspace/lumina-walk-v6/ を参照できますが、肘を含む最新の一般化した動きをそのまま持つとは限りません。

元のユーザー要望として、翼が髪の後ろへ隠れすぎないこと、手と指を伸ばしきらないこと、首の切り口・髪の束が喉元の突起に見えないことを引き継ぎます。頭・髪・輪・翼の前後関係は、方向と体の動きに合わせて決めます。

画像を描き直す場合も、元の歩行タイミングや各関節の位置まで一度に変更しない方が、見た目の差分を判断しやすくなります。生成プロンプト、使った参照画像、採用した画像、切り出し方法とpivotを記録してください。
